# Praise UI audit — 17 October 2026

## Status update — 27 October 2026

The findings below describe the 17 October audit. Since that audit:

- Lyrics share one dark-green reading surface in the song reader and performance
  mode. The lyrics column is bounded to 760 logical pixels.
- Line-by-line display has been removed. Saved selections fall back to Sections,
  resolving A05 by removing the affected mode.
- Practice videos now follow lyrics (part of A15); failure/offline recovery still
  needs work.
- The Settings feature switches have been removed. Every tool is available for
  every role, including installations with previously disabled switches. Role
  changes no longer replace tool settings (relevant to A25 and A29). Per-song
  display choices remain available in Song controls.

Other findings and device-test limits remain historical evidence and have not
been re-audited here. The original report follows.

Scope: Flutter onboarding, Songs/search, Favorites, Lists, list detail/reordering,
song picker, Add to List, song reader, music controls/metronome, notes, photos,
custom-song creation/editing/drafts, performance mode, export/import dialogs,
Settings/privacy, feedback, and the separate `song-editor` web UI.

This is an audit, not an implementation. Production application code is unchanged.
Findings distinguish reproduced failures from source-confirmed behavior and design
improvements. Earlier October 12 findings were checked against current code; fixed
onboarding scrolling, change-role routing, contextual chord availability, search
debouncing, import matching previews, and photo-plus-text song PDF handling are
not repeated as outstanding bugs.

## Evidence and limits

- `flutter analyze --no-pub`: passed before temporary emulator instrumentation.
- Existing `flutter test --no-pub`: **151 tests passed**.
- Android device walkthrough: **12 captures completed; one application UI
  assertion reproduced** (A30 below). The run correctly failed its final
  zero-error assertion. This is not an all-clear device pass.
- Additional audit probes exercise full screens with the real bundled Telugu
  font, Material icons, and the app theme: **6 failures / 8 probes**. Ordinary
  reader layout and narrow Settings passed. [Probe output](qa/ui-audit-2026-10-17/widget-probe-results.txt).
- Song Studio was visually inspected in the browser at desktop and 390×844.
- Android emulator evidence is recorded below after the device run. Widget
  rendering alone does not establish Android keyboard behavior, TalkBack,
  native photo picking, YouTube playback, or platform sharing.
- P1 = address first because work/content can be lost, hidden, or inaccessible;
  P2 = important usability/accessibility issue; P3 = product/design improvement.
- **Reproduced** means an automated widget probe demonstrated the failure.
  **Source** means the current control flow or visible strings establish it.
  **Improvement** is a design recommendation, not a claimed runtime failure.

## Android emulator run

Local AVD: `Flutter_Android`, ARM64 Google APIs / Android API 36, Pixel 7 profile.
The app was built, installed, and exercised on the local emulator using software
rendering (`--enable-software-rendering --no-enable-impeller`). The walkthrough
completed **12 captures** across Songs, empty search/clear, reader, expanded
controls, metronome, Favorites, Lists, Settings/features, appearance, lyrics
preferences, Add a song, and the manual editor. It recorded **one application
scheduler assertion**: duplicate default FAB Hero tags (A30). The final zero-error
check therefore failed; this is useful defect evidence, not a passing device run.

Early attempts encountered emulator boot/ADB/graphics stalls and audit-harness
redirect, selection, scrolling, and driver-timeout problems. Those are excluded
from the application defect count. The temporary harness and dependency changes
were removed after evidence collection. The application remains running in the
emulator; no fixes to production application code were made.

The six additional reproduced failures are widget-test findings. Native photo
selection, TalkBack, platform sharing, external video playback, imports, draft
recovery on Android, and 200% text on the emulator remain unverified. Device
captures use ordinary text scaling; the emulator's software-rendering speed is
not a physical-device performance result.
